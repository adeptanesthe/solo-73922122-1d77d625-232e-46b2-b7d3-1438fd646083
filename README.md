# 再生塑料配方试配筛选（质检模型 + 最优改配求解 + 当班模型更新）

面向再生塑料配方研究员的网页工具：录入原配方与各原料的上下限、锁定项后，
在**合格概率 ≥ 0.7** 的约束下，按 **先最少改变原料种数、再最小化总克数改变量**
的字典序求出最优试配方案；只有求解器**证明**无解才报无解，求解失败单独报告。
另提供「当班试配模型更新」页面：录入 5～30 条已检四料配方及实测 0/1 标签，
整体替换上次实测批次后按原规格与种子重训随机森林并原子发布新版。

## 技术栈与模型

- **FastAPI** 提供网页与 JSON API；**scikit-learn** 训练随机森林；**z3-solver** 求解。
- 质检模型：`RandomForestClassifier(n_estimators=5, max_depth=3, random_state=20241117)`，
  在固定种子生成的合成数据上训练（Dirichlet 采样的配方比例 + 含噪质检规则，阈值取中位数
  使类别均衡）。基线每次启动以同一种子重训，结果确定（自测验证同种子重训一致）。
- **当班更新**：质检工程师提交 5～30 条实测记录（4 种原料整数克数、总重恰为 1000 克、
  标签 0/1）。本批记录**整体替换**上次实测批次，与固定合成训练集合并后按**原超参和原种子**
  重训；合成记录权重 1，**每条实测记录权重 20**（`sample_weight`）。
- 配方为 4 种原料的整数克数，总重 1000 克；模型输入为克数 ÷ 1000 的 **float32** 比例。

## 模型版次与原子发布

- 每个版次是一份不可变 `ModelSnapshot`（`app/versioning.py`），**同时**持有：候选分类器、
  供 z3 求解的树结构 `ForestSpec`、经求解器实测的可行/无解样例、所用实测批次与版次号。
- 一次更新依次完成「输入校验 → 重训分类器 → 导出 z3 树结构 → 重建可行/无解样例」，
  **全部成功后才以单次引用赋值原子切换**当前快照；任一步失败则旧版快照连同其所用
  实测批次原样保留，服务继续在旧版上运行，并在 `/api/model/status` 记录失败原因。
- 同一时刻只允许一个更新任务，并发提交返回 `409`。
- `/api/solve` 在整次请求内只读取一次快照引用，因此一份建议的**森林约束、原分类器复算
  概率与版次标识必然来自同一模型快照**；响应携带 `model_version`。更新期间在途的旧版
  求解照常完成，不受影响。
- 前端每 3 秒轮询版次：发布页提交后，试配页无需刷新即感知新版并**立即撤下旧建议**；
  迟到的旧版响应若 `model_version` 与当前版次不符，也直接丢弃，绝不作为新版建议显示。

## z3 线程模型（重要实现细节）

z3-solver 的 Python 绑定存在**线程亲和性**：即使加锁串行化，只要在不同线程构造/求解
z3 对象，就可能破坏其线程本地状态（实测出现过 `solver_failure` 与段错误）。
FastAPI 同步端点运行在线程池中，因此本服务用**单一专用 z3 工作线程 + 任务队列**
（`app/solver.py: Z3_RUNNER`）承载全部 z3 调用，请求线程只取回纯 Python 结果；
只读的 sklearn 概率复算不涉及 z3，仍在请求线程执行。自测含 6 线程并发与
120 请求压力回归，真实 uvicorn 服务下并发求解零失败。

## 求解语义（与分类器严格一致）

- sklearn 树内部以 float32 特征与 float64 阈值比较。求解器把每个分裂条件
  `float32(g/1000) <= τ` 预计算为等价的**整数截断** `g <= K`（`app/model.py: cutoff_left`），
  因此 z3 中的约束与原分类器的实际阈值语义逐点一致（自测第 2 项对全部阈值 × 0–1000 克逐点核对）。
- 森林概率 = 5 片叶子概率（精确有理数）之和 / 5 ≥ 0.7，以精确有理数编码进 z3。
- 字典序优化用**两阶段**实现：先最小化改动种数，固定该最优值后再最小化总改动克数。
- 每份建议解出后**用原 sklearn 分类器复算概率**（float32 输入），未通过复核则按求解失败上报，
  绝不当作合格建议展示。
- 结果状态严格区分：`ok`（已证明最优）/ `infeasible`（z3 判定 unsat，即证明无解）/
  `invalid`（输入不合法）/ `solver_failure`（z3 unknown、超时或异常，**不**当作无解）。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

### 本地开发

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 页面与交互

- **试配页（`/`，原入口保留）**：录入 4 种原料的原配方克数、各自下限/上限、锁定勾选；
  总重须为 1000 克。页头显示当前模型版次，并提供到更新页的链接。
- 「载入可行样例」「载入无解样例」：样例随**当前模型快照**由真实模型 + 求解器**实测验证**
  后生成（`app/samples.py`），发布新版时随快照一并重建；可行样例含锁定项，无解样例为
  上下限把配方逼入不合格区域的情形。
- **计算期间可随时修改**：任何输入修改会立即撤下旧建议（清空结果区）、中止在途请求；
  迟到的旧响应按请求序号（epoch）比对后直接丢弃，不会恢复显示（`app/static/index.html`）。
- **版次撤回**：轮询发现新版发布，或迟到响应的 `model_version` 与当前版次不一致时，
  立即撤下旧建议且不显示跨版次结果。
- 结果展示：合格概率（原分类器复算值）、逐原料改动明细、改动种数与总克数、最优性结论、
  求解耗时与模型版次。
- **模型更新页（`/update`）**：动态表格录入 5～30 条记录（可增删行、填入示例批次），
  客户端先校验条数/整数/总重/标签再提交；展示当前版次、所用实测批次、更新在途标志与
  上次更新成败；成功显示新版号与标签分布，失败明确提示旧版继续可用。

## API

| 端点 | 说明 |
| --- | --- |
| `GET /` | 试配单页网页（原入口） |
| `GET /update` | 当班模型更新网页 |
| `GET /api/meta` | 当前快照的模型规格与版次（树数、深度、种子、阈值、特征名、实测条数） |
| `GET /api/model/status` | 当前版次、所用实测批次、更新在途标志、上次更新结果 |
| `POST /api/model/update` | 整体替换实测批次并重训发布；体：`{records:[{grams:[4 个整数],label:0\|1}]}`；成功 200，输入非法 400，更新在途 409，重训/样例失败 422 且旧版保留 |
| `GET /api/samples` | 当前快照下经求解器实测的可行 / 无解样例（含 `model_version`） |
| `POST /api/solve` | 求解；体：`{original, lower, upper, locked}`（各 4 元）；响应含 `model_version` |
